# 零基础转型端侧 Agent 视频跟学指南

> 本文为历史方案。当前已按个人背景和B站主课结构统一为 [[Agent学习执行总表与视频导航]]，不再并行执行多个周计划。

## 适用对象与目标

> 当前执行顺序以 [[AI智能体技术全景与分阶段学习主计划]] 为准。跳过 Python 语法不表示跳过 LLM/Agent 认知基础；应先完成概念阶段，再开始工具项目。

> 最新背景确认：用户已有一定 Python 基础，明确希望跳过基础语法，在后续项目中同步补知识。因此第 2—3 周不再作为必修；直接从第 4 周的 Agent 项目开始，遇到 JSON、异常处理、依赖管理、SDK/HTTP、异步或流式接口问题时按需补齐。建议进度调整为 8—10 周，具体以验收为准；原 12 周安排保留为参考。

面向已有 Android 系统开发背景、AI/Agent 与 Python 可以从零起步的学习者。目标是从视频跟练过渡到可演示的 Android 工具调用助手；不是从零学习所有软件开发，也不承诺完成即达到专家职级。

每周按 10—12 小时估算：四个工作日每天 1 小时，周末合计 6—8 小时。计划 12 周；Python 已熟练可压缩第 2—3 周。时间为本指南估计，不是课程官方完成时长。

贯穿项目：学习笔记与待办助手。先支持查询自己准备的笔记、读取待办、确认后创建待办，后续迁移 Kotlin，增加本地推理和服务化。各阶段是练习建议，未创建代码工程，用户也尚未确认按此执行。

## 第 0 步：准备学习环境（半天至一天）

1. 打开 A 的课程页，找到上述三个主题；先确认能播放中文视频。
2. 注册视频平台账号，确认 B/C 的视频和代码环境能打开。英语课使用当前可用字幕/讲稿；需要中文时翻译讲稿，不预设有官方中文字幕。
3. 准备 Windows 开发机、Python、编辑器、Android Studio 与一台可调试手机；前半段先使用课程提供的 Notebook（如果账号可用）。
4. 本机实验单独建目录和虚拟环境，不混装不同课程依赖；先使用课程提供的依赖版本。Notebook 有辅助函数时先查看对应文件，不把隐藏封装当成模型标准接口。
5. 模型优先使用课程支持的接口。若改用其他供应商，分别验证鉴权、工具调用、结构化输出和流式事件格式，不假定兼容接口完全一致。
6. 云密钥仅放开发机环境变量或受保护服务端，不写入 APK、源码或笔记。设置实验消费上限。

环境验收：能运行 Python 输出一句文字，能打开一个课程代码示例，能在手机运行一个空 Android App。前半段不需要购买 GPU。

## 第 1 周：建立概念（A，中文视频）

### 观看顺序

1. “一堂课搞懂生成式 AI”：理解模型输入输出、上下文与生成。
2. “AI Agent”：理解工具、规划和执行反馈。
3. “剖析大型语言模型内部运作逻辑”：先建立 Token 与生成过程的直觉，不要求推公式。

### 每天的动作

- 第 1 天：看生成式 AI 前半部分，记录 5 个不懂的词。
- 第 2 天：看完并手动画一次请求/响应。
- 第 3 天：看 Agent 课前半部分，列出聊天与工具执行的区别。
- 第 4 天：看完 Agent 课，画出一次工具调用的数据流。
- 周末：补模型内部逻辑，准备 5 条假笔记和 10 个用户问题。

### 作业与验收

用自己的话解释 Prompt、Token、上下文、工具、工作流、Agent；画出“模型提出调用—程序校验执行—结果回传”的循环。明确不要求模型输出隐藏推理过程，只记录可观察的调用与结果。

若解释不清，回看具体片段；不先跳到多 Agent。

## 第 2 周：Python 语法（B 的模块 1—2）

### 必看课节

- Running your first program、Data in Python、Variables。
- Functions: Actions on Data。
- Repeating tasks with for loops。
- Prioritizing tasks with dictionaries and AI。
- Comparing data in Python、Helping AI make decisions。

其余课节按顺序跟练；已有 Java 经验的“编程是什么”部分可以快进。

### 作业

用列表/字典保存 5 条笔记，写 `search_notes(query)` 和 `list_todos()`。此时不接模型，直接用函数返回检索结果。

验收：能独立写函数、循环、条件判断，处理空结果；能解释字典与 JSON 文本的区别。不能脱离视频完成时，先重做语法练习。

## 第 3 周：文件、依赖与模型 API（B 的模块 3—4）

### 必看课节

- Using files in Python、Loading and using your own data。
- Turning code blocks into reusable functions。
- Using functions from a local file、Installing packages。
- APIs to get data from the web、APIs to use AI models。
- 本机 Python 安装章节。

### 作业

1. 把笔记与待办保存为 JSON 文件，程序重启仍能读取。
2. 从本地终端调用一次模型，打印脱敏后的请求与响应结构。
3. 分别模拟错误密钥、网络失败和格式错误，记录错误位置。
4. 补学课程未充分覆盖的异常处理、虚拟环境、环境变量与 JSON Schema，以官方文档为准。

验收：不依赖 Notebook 隐藏函数也能说明请求怎样发送、凭据从哪读取、响应怎样解析。课程调用 SDK 与 HTTP 接口之间的关系能讲清楚。

## 第 4 周：手写第一个 Agent（C 的开头部分）

观看 Introduction 与 Build an Agent from Scratch；视频短不意味着一遍即可掌握，每段代码暂停运行。

### 作业

先复现课程原例，再替换为 `search_notes` 和 `list_todos`。增加步数与时间上限，记录每步的工具名、脱敏参数、结果、耗时和错误。

早期例子可能使用文本动作协议或解析表达式：理解执行循环后，实际工具参数应使用显式结构和校验，不对模型输出执行任意 `eval` 或 shell。

验收输入：“查找 Android Agent 学习相关笔记，再告诉我还缺什么。”答案需要来自真实工具结果。伪造检索结果不算成功。

## 第 5 周：图编排、检索与状态（C 的中间部分）

观看 LangGraph Components、Agentic Search Tools、Persistence and Streaming。

### 作业

- 把原例的状态、节点、条件边映射到自己的助手，画状态图。
- 先按课程复现搜索工具，再换成自己笔记的本地关键词检索。此替换是本指南作业，不是课程已有的本地 RAG 项目。
- 为会话分配 ID，隔离两个用户/会话，持久化对话与任务状态。
- 展示流式事件，区分生成文本与工具执行状态。

验收：会话不串数据；重启能读取历史；理解恢复状态不等于可以安全重放写操作。库 API 变化时先对齐课程版本，避免同时升级全部依赖。

## 第 6 周：人工确认与有副作用的工具（C 的后半部分）

观看 Human in the Loop 与 Essay Writer；后者用于观察完整流程，自己的项目继续做助手，不必再开写作项目。

### 作业

增加 `create_todo(title)`：工具调用先生成待确认动作，用户批准后执行；拒绝则不写入。为动作分配持久化 ID，重复请求不重复创建。

加入取消、工具失败和超时；结果未知时先查实际状态，再决定是否重试。区分模型会话、任务检查点、工具副作用三者。

验收：同一创建动作重复执行三次只产生一条待办；拒绝/取消后无新增记录；任务达到预算上限会结束。

## 第 7 周：评测（D 的前半部分）

观看前置介绍、Lab 1、Tracing agents、Lab 2，以及路由/技能评测部分与 Lab 3。

### 作业

先复现课程实验，再为自己的助手准备 30 个起步案例：10 个笔记搜索、10 个待办操作、10 个异常/取消/越权场景。此数量仅作学习样本，不代表生产评测充分。

每条写清输入、允许工具、预期结果与禁止行为。记录工具选择、参数、最终结果和耗时。个人内容使用假数据。

验收：可批量重跑，能区分模型选错工具与工具实现出错。不要仅靠模型自评判断写操作是否成功。

## 第 8 周：实验与回归（D 的后半部分）

观看轨迹评测与 Lab 4、实验结构与 Lab 5、LLM-as-a-judge 改进及监控部分。

### 作业

固定任务集，只改一个变量（工具描述或提示词），比较改前/改后的成功率、错误操作、调用步数和耗时。写入一页报告，保留失败例子。

验收：能说明一次改进为什么有效、有什么代价。进入 Android 阶段前保留可运行的 Python 基线。

## 第 9 周：迁移 Kotlin（E，自编实验，无对应完整视频）

按需阅读协程/Flow 文档。先迁移接口和状态，再做 UI；不要求把 Python 框架搬进 APK。

建议代码职责：ModelClient（模型通信）、ToolRegistry（工具定义）、ToolExecutor（校验执行）、AgentRunner（循环与预算）、SessionStore（持久化）、ViewModel（UI 状态）。

先使用假模型返回固定工具调用，验证 Kotlin 执行器；再接真实模型。云端调用走持有凭据且有适当认证的开发代理，或供应商正式支持的客户端认证方案。

验收：与 Python 基线完成相同任务，UI 显示执行状态；Android 客户端不包含长期云密钥。

## 第 10 周：Android 生命周期与工具持久化（自编实验）

使用 Room 管理笔记、待办、任务与工具操作 ID。处理旋转、离开页面、用户取消与进程重建。明确哪些任务允许后台继续，遵守系统执行限制。

验收：旋转不重复请求、恢复不重复创建；主动取消后不继续执行下一步工具。对已经提交的操作应查询结果，不把取消等同于回滚。

## 第 11 周：本地推理（F，自编实验）

按官方支持清单选择模型与设备，先运行最小示例，再接入 ModelClient。先让本地模型承担摘要/分类；是否用于工具规划由实际测试决定。

测量模型加载、首 Token、输出长度、总耗时、内存与持续运行。记录设备、运行时和模型版本。端云回退先检查用户授权与数据上传策略。

验收：离线可完成明确的本地任务；模型不可用有清晰状态；至少产出一份设备测试记录。LiteRT-LM 仅为学习选项，不代表所有手机厂采用该方案。

## 第 12 周：系统能力服务化与作品交付（自编实验）

根据时间将一个受控工具拆成独立进程服务，用 AIDL/Binder 暴露，验证断连、服务死亡和重连。作为普通 App 仅操作自己的数据，系统权限能力在可控系统环境另行验证。

交付：演示、架构图、核心代码说明、评测数据、性能记录、三个失败案例及修复说明。时间不足时可将服务化延后一到两周，不压缩评测。

## 每次学习的固定方法

1. 观看 15—30 分钟，写下一个具体问题。
2. 运行原例，检查输入输出和状态，不只点击 Run All。
3. 改一个参数或工具，观察差异。
4. 关闭视频独立重做关键部分。
5. 记录“今天完成什么、失败原因、下一步”。

英语困难时：先看课节标题和讲稿翻译，再看视频和代码；记录中英术语对照。若无法访问或没有可用字幕，应调整资源而不是假定存在中文字幕。中文概念课可先行，但不能替代代码练习。

## 常见卡点处理

| 问题 | 优先检查 |
| --- | --- |
| 示例无法运行 | Python 与依赖版本、辅助文件、环境变量、接口是否仍支持；保留完整脱敏错误 |
| 模型不调用工具 | 当前接口/模型是否支持、工具定义、提示是否需要工具、是否只声明未执行 |
| 工具执行后反复循环 | 工具结果是否回传、消息关联是否正确、是否有预算与停止条件 |
| Android UI 卡顿 | 主线程 I/O、长解析、阻塞调用与生命周期绑定 |
| 取消后仍创建数据 | 写操作是否已提交、取消传播、执行前授权检查、结果查询和幂等记录 |
| 本地推理失败 | 模型格式、运行时/设备/后端支持、可用内存及资源释放 |
