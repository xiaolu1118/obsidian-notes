## 职业定位建议

以“有 Android 系统工程背景的 Agent 应用工程师”为切入点，优先考虑研发提效、终端智能体和设备诊断场景，逐步积累专家岗位需要的架构与交付能力。

核心补课方向：把具有不确定性的模型接入需要稳定交付的软件系统，包括模型基础、上下文和检索、工具调用、效果评测及 Python 服务开发。

## 学习内容与优先级

### 第一层：Python 和模型调用基础

目标：独立开发并部署一个模型应用服务。

- Python：类型标注、异步编程、异常处理、依赖管理。
- 服务端：FastAPI、HTTP、SSE 流式输出、数据库、Docker。
- 模型基础：Token、上下文窗口、Embedding、采样、幻觉、结构化输出。
- API 实践：多轮会话、超时、重试、限流、成本统计。
- 原理基础：理解 Transformer、注意力及训练与推理的基本区别；初期无需从零训练大模型。

### 第二层：Agent 核心执行机制

需要能独立实现并解释以下链路：

用户目标 → 构造上下文 → 模型选择工具 → 校验参数和权限 → 执行工具 → 返回结果 → 继续执行或结束。

- Tool Calling、JSON Schema、工具描述设计。
- 固定工作流与自主 Agent 的适用边界。
- 状态管理、执行预算、停止条件、失败恢复。
- 人工确认、幂等性与重复执行处理。
- MCP 的用途、客户端与服务端关系、授权边界。

建议先用原生 SDK 实现完整循环，再选择一个编排框架深入。框架需要服务于明确的问题。

### 第三层：RAG 和上下文工程

目标：让模型基于代码、文档和历史案例可靠工作。

- 文档解析、切块、元数据、增量更新。
- 关键词检索、向量检索、混合检索、重排序。
- 代码检索与普通文档检索的区别。
- 引用溯源、信息冲突、无答案时的处理。
- 会话历史压缩、任务状态与长期记忆的边界。

排错时区分：没有检索到、检索错误、模型拿到材料后理解错误。

### 第四层：评测与生产工程

目标：能够量化效果，定位失败，并稳定交付。

- 建立真实任务集，定义成功和失败。
- 记录模型调用、工具执行、检索和最终结果。
- 衡量任务成功率、错误操作率、延迟及单任务成本。
- 对模型、提示词、检索策略、工具设计做对照实验。
- 处理提示注入、越权调用、数据泄漏和工具失败。
- 实现回归验证、灰度发布、回滚。

## 主线项目：Android 系统故障诊断 Agent

### 项目目标

利用 Android 系统经验，做出有技术深度、可演示、可评测的应用。

输入：经过脱敏的 bugreport、logcat、ANR traces、tombstone，以及对应版本的代码和文档。

处理流程：

1. 识别故障类型，提取关键时间线。
2. 调用解析、检索和代码查询工具。
3. 给出根因假设，并逐项关联证据。
4. 区分已确认事实、推测和缺失信息。
5. 输出下一步排查方案。

### 迭代安排

| 阶段 | 交付内容 | 体现的能力 |
| --- | --- | --- |
| V1 | 日志解析工具、结构化诊断报告 | Python、模型调用、工具设计 |
| V2 | 关联 AOSP 文档、源码、历史案例 | RAG、上下文组织、证据溯源 |
| V3 | 多步调查、状态保存、失败恢复 | Agent 编排与可靠性 |
| V4 | 固定评测集、对照实验、部署监控 | 架构判断、效果优化 |

设计原则：日志解析、时间计算和关键字段提取尽量交给确定性代码；模型负责综合分析和提出调查方向，便于定位错误与评测。

后续可扩展终端操作项目：通过 ADB 完成测试和复现任务。修改设备状态的操作需要权限检查和人工确认机制。

## 建议学习节奏

假设每周投入 10—15 小时，按 16 周安排。此安排是学习建议，不意味着完成后即可获得专家岗位。

| 时间 | 重点 | 交付物 |
| --- | --- | --- |
| 第 1—4 周 | Python、模型 API、结构化输出、工具调用 | 日志分析服务 V1 |
| 第 5—8 周 | 检索、Embedding、混合检索、引用 | 可追溯的知识检索与诊断 |
| 第 9—12 周 | 编排、持久化、恢复、MCP | 完整多步诊断 Agent |
| 第 13—16 周 | 评测、成本、延迟、安全、部署 | 可演示系统和实验报告 |

每个阶段保留：代码、设计取舍、效果数据。用于复盘和面试展示。

## 投入取舍

- 编排框架选择一个深入，避免同时铺开多个框架。
- 微调按项目需要再学。
- 单 Agent 出现明确瓶颈后，再考虑多 Agent。
- 机器人开发保留为后续方向，当前先打通 Agent 主线。
- 用系统诊断或终端研发工具建立差异化，再用评测、架构和交付能力支撑专家岗位定位。
