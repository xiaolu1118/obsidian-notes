## 一、先记住的关键点

以下为跨章节概括，具体来源见详解各节：

1. **复杂生成可以拆成基本单位的预测**：理解 Token 和条件概率，是理解语言模型的入口；这不是说所有生成模型都只能自回归。
2. **训练和推理是两个阶段**：训练调整参数；推理利用已有参数处理新输入。提示、外部记忆和工具能改变当前行为，却不等于重新训练。
3. **Agent 把一次回答变成与环境交互的循环**：目标、观察、动作、反馈，以及经验、工具和规划，是 P2 的重点。
4. **模型内部机制不能仅靠模型自述来解释**：行为观察、内部表征分析与因果干预有不同证据强度。
5. **架构要结合问题评估**：Transformer 与 Mamba 的比较涉及信息访问、状态压缩、计算和并行能力，不能从标题推出谁必然取代谁。
6. **预训练、对齐与后训练各有作用，也有代价**：新增任务能力时，应同时检查旧能力和对齐行为是否退化。
7. **更多推理计算是一种资源分配方法**：长过程、多次尝试和验证可以有帮助，但更长不保证更正确。
8. **评测要回到真实任务**：模型编辑和融合也必须检查副作用；语音生成进一步把 Token 的概念扩展到声音。

## 三、结合当前目标的学习顺序（建议，未确认）

已确认背景：Android 系统框架和 Python 有基础，AI Agent 尚处入门阶段，目标为手机厂智能体与应用开发。以下是建议，不代表用户已承诺执行。

- **第一轮：P1 → P2**。建立模型、工具、记忆和执行器的边界，同时手写最小工具循环。
- **第二轮：P3 的概念部分 → P8 → P9 → P10**。理解模型局限，加入验证、预算和评测。P3 的研究细节可以回看。
- **第三轮：P5 → P6**。理解微调适用范围和回归风险，再判断项目是否需要改参数。
- **语音项目分支：P13**。文本 Agent 跑通后再加入语音交互。
- **进阶选修：P4、P7、P11、P12**。与模型架构、训练或研究岗位相关时深入；不作为完成首个 Agent 的前置条件。

本课程主要建立概念与研究视野。项目开发仍需补充 API、结构化输出、参数校验、异常处理、日志、状态持久化与 Android 集成，详见已有主计划。
