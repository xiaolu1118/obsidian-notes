## 一个贯穿全程的 WindowLab

建议创建独立 Android Demo，不需要从零搭系统业务；本次仅完成项目设计，尚未创建代码或部署应用。

| 页面/开关 | 实验目的 | 输出证据 |
|---|---|---|
| 两个普通 Activity | 启动、返回、可见与焦点变化 | 生命周期日志、Task/Window 树、首帧 |
| Dialog 与 PopupWindow | token、type、父子窗口、dim 和焦点 | flags 对照、WM/SF/input dump |
| EditText 与 Insets 显示面板 | IME、系统栏、resize/pan | Insets 回调值、frame、录屏 |
| edge-to-edge 与适配开关 | App 布局与系统策略边界 | target SDK、系统版本、遮挡对照 |
| 旋转与配置日志 | bounds、rotation、重建与无缝旋转 | configuration、trace、Surface 变换 |
| 独立 SurfaceView | 内容生产与窗口管理边界 | layer/buffer 证据；注意帧工具覆盖限制 |
| debug 主线程负载开关 | 可控地观察 App 卡顿 | 正常/异常 Perfetto；仅实验应用使用 |
| PiP 或可调整尺寸 Activity | 多窗口与 organizer 行为 | Task 重挂、bounds、转场 |

每个开关一次只改一个条件。优先用应用行为构造问题，只有理解链路后才在独立 AOSP 实验分支注入系统错误。禁用负载开关后确认恢复正常；不将实验改动混入产品代码。

## 最低案例集

- [ ] 正常窗口从 add 到首帧的时序基线。
- [ ] Dialog/触摸区域导致输入异常的可控案例。
- [ ] Insets/IME 或旋转布局异常案例。
- [ ] 黑屏/闪烁的窗口与图层联合分析案例。
- [ ] Shell Transition 或分屏完整时间线案例。
- [ ] 一个有实际 patch 和回归结果的修复案例。

前五项可以是学习实验；最终项目应争取真实缺陷。标注“官方案例复现”“自建实验”“真实项目缺陷”，避免把练习写成工作业绩。
