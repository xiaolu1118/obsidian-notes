# 李宏毅 2025 机器学习核心知识详解

关联 [[李宏毅2025机器学习课程视频导读]]、[[AI智能体技术全景与分阶段学习主计划]]、[[端侧Agent入门实战计划]]；返回 [[索引]]。

> 本文根据指定合集的分 P 信息和官方课件整理，非逐字视频摘要。各节“课件要点”是压缩概括；“理解补充”“工程建议”是为学习提供的解释，不冒充讲师原话。P7、P10 未取得正文，特别标注。具体核验范围见导读。

## 1. P1：生成式 AI、Token 与自回归

**课件要点**：复杂输出可由基本单位组成；按顺序预测下一个单位，可以把生成拆解为重复执行的预测任务。课程进一步连接深度网络、推理时计算、模型架构和训练参数。

**理解补充**：Token 是模型使用的表示单位，文本中可能是字、子词或其他片段，不能固定按“一个汉字一个 Token”计算。对自回归文本模型，可写为：

$$P(y\mid x)=\prod_{t=1}^{T}P(y_t\mid x,y_{<t})$$

这里 $x$ 是输入，$y_{<t}$ 是已经生成的内容。模型逐步预测条件分布，解码策略再决定具体输出。自回归是重要路径，但不是全部生成模型的统一实现。

**必须分清**：架构描述计算结构；参数数值由训练得到；推理使用已有参数。把新资料放进提示可改变本次输出，不等于资料已写入模型参数。

来源：[第1讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/introduction.pdf)。

## 2. P2：Agent 的交互循环、经验、工具与规划

**课件要点**：LLM 可以根据目标和观察生成动作，再利用新的观察继续决策。本讲以现有模型构建 Agent，不训练模型；重点包括经验记忆的读取、写入与反思，函数工具调用和规划。

**理解补充**：

```text
用户目标 → 当前状态与相关记忆 → 模型选择动作
                              ↓
结束并回答 ← 验证结果 ← 工具执行 ← 程序校验
                 ↓
             更新观察，再次决策
```

模型生成调用意图，宿主程序负责实际执行。一次搜索可构成固定流程；是否属于自主 Agent，要看模型是否参与决定后续动作。

短期历史、任务状态和长期记忆用途不同。长期记忆可通过检索取回相关经验，而不是把全部历史塞入提示；反思文本也需要后续结果检验。记住一次失败并在下次提示中提醒模型，仍可完全不改参数。

来源：[第2讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/ai_agent.pdf)。工程练习见第 14 节。

## 3. P3：模型内部机制与可解释性

**课件要点**：从单个神经元、一层表征、一群神经元，以及模型自己描述想法等角度研究内部行为；涉及功能向量与稀疏自编码器（SAE）。

**理解补充**：一个神经元可能响应多个特征，一个概念也可能分布于多个神经元。SAE 尝试把内部激活分解为较稀疏的特征组合，以便分析，但不等于彻底读懂模型。

观察到某个激活与行为相关，只是相关证据；改变它后行为发生预期变化，才提供进一步因果证据，仍需控制实验条件。模型输出的解释文本不是对内部计算过程的直接测量。

**学习目标**：区分输出行为、内部表征与因果干预三种证据；应用开发初期先掌握局限，不必先复现全部解释性研究。

来源：[第3讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/model_inside.pdf)。

## 4. P4：Transformer、循环状态与 Mamba

**课件要点**：从序列处理出发比较注意力、RNN 风格计算及 Mamba 等架构，关注每种结构存在的理由。

**理解补充**：标准全注意力直接建立位置之间的交互，注意力部分的计算量随序列长度呈平方增长。循环式方法把过去的信息压入状态，可能减少逐步推理开销，但状态压缩也影响信息保留和访问方式。Mamba 的选择性状态空间机制属于这一取舍中的重要研究路径。

不能只凭复杂度或课程标题判断模型优劣；实际表现还取决于硬件、实现、训练和任务。融合注意力与状态模型也是设计空间的一部分。

**Android 侧启示（建议）**：选型用真机测量首 Token 延迟、吞吐、内存和任务成功率，架构名称本身不足以决定体验。

来源：[第4讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/mamba.pdf)。

## 5. P5：预训练与对齐

**课件要点**：预训练提供广泛基础，对齐影响如何调用和表现这些能力；对齐资料的质量和位置很重要。课件也讨论数据改写、多样性、质量及有限计算预算的取舍。

**理解补充**：预训练常使用大规模自监督目标；监督微调（SFT）通过输入输出示例塑造行为；偏好学习或强化学习是其他后训练路径。不能把“少量高质量对齐数据有效”推广为“所有能力都能靠少量数据获得”。

“知道某事实”“能按某种问法答对”“能稳定完成相关任务”是不同要求。对反向提问、改写问法和组合任务，应单独验证。

**工程建议**：先明确需求是补充可检索资料、改变输出习惯，还是提升任务能力，再决定使用上下文、工具或微调。

来源：[第5讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/pretrain.pdf)。

## 6. P6：后训练与灾难性遗忘

**课件要点**：对已对齐模型继续训练，可能提升新任务却损害原有能力或对齐行为；经验回放是缓解路线之一，但原始训练数据往往不可得。

**理解补充**：遗忘不只是“忘了一个事实”，也可能体现为指令遵循、输出格式、通用任务或安全行为下降。新任务分数上涨，不足以证明模型整体变好。

**工程建议**：保留微调前基线，用相同测试集比较新任务与旧任务；记录数据版本与训练设置；为回退保留原模型。数据混合、约束更新或参数高效方法都需实测，不能承诺某一方法自动消除遗忘。

来源：[第6讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/post_training.pdf)。

## 7. P7：多 GPU 训练（仅核验主题）

**已核实**：B 站分 P 标题提到多 GPU、DeepSpeed、Liger Kernel 和 Flash Attention；官方页也有多 GPU 训练补充视频。本次未取得对应讲稿，下面是通用背景，不是这节课的详细摘要。

**通用补充**：训练显存不仅存权重，还涉及梯度、优化器状态和中间激活。数据并行、参数/状态分片与模型并行处理不同瓶颈；高效算子与注意力实现通常改善运算或内存访问效率，并不自动让模型知识更多。

**建议**：当前优先完成模型调用和 Agent 项目；进入训练方向后，再学习显存估算、混合精度、梯度累积和分布式通信。

来源：[官方课程页](https://speech.ee.ntu.edu.tw/~hylee/ml/2025-spring.php)与导读中的 B 站 P7 链接。具体实现待补核。

## 8. P8：推理能力与推理时计算

**课件要点**：课程区分增强思维链、安排推论工作流、模仿推理过程和以结果为导向的强化学习。前两者可以不改参数，后两者涉及训练。

**理解补充**：推理时计算可用于更长生成、尝试多个候选、搜索或验证；其收益取决于任务和验证信号。模仿学习依赖示范质量；强化学习依赖奖励是否真正对应目标，奖励可被钻空子。

**工程建议**：编码任务优先接入编译器、单元测试或静态检查等可执行证据。让模型自查可作为一步，却不能取代外部验证。比较方案时同时固定模型、任务集和总预算，避免把多次调用带来的收益误归因于某一句提示。

来源：[第7讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/reasoning.pdf)。

## 9. P9：推理长度够用即可

**课件要点**：讨论“想太多”及控制推理长度，可从提示、工作流、训练数据和奖励等角度处理。

**理解补充**：长过程增加成本和等待时间，也可能引入额外错误；短答案则可能省略必要检查。应按质量与预算的联合目标选择，而不是只优化字数。

**工程建议**：简单查询直接答复，复杂问题分配更多步骤；设置调用次数、输出长度、超时和停止条件。端侧应用进一步记录耗电、温升及交互等待。这里是应用设计建议，不是课程已证明的最佳参数。

来源：[第8讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/reason_shorter.pdf)。

## 10. P10：评测（主题已核验，正文待补）

**已核实**：官方页与 B 站目录均有模型评估主题。本次未成功读取 `reason_eval.pdf`，以下是通用评测建议，不归为讲师的具体论断。

| 评测对象 | 最小检查 | 常见误判 |
| --- | --- | --- |
| 文本回答 | 正确性、证据、任务约束 | 写得流畅就算正确 |
| 检索问答 | 资料能否召回、引用能否支持结论 | 回答有引用就算有依据 |
| 工具执行 | 工具选择、参数、执行结果、最终状态 | 模型说“已完成”就算完成 |
| 连续任务 | 成功率、步骤数、失败恢复、成本 | 单次演示成功等于稳定 |

建议固定任务集、保留失败案例并复测。使用模型裁判时，明确评分准则并抽样人工核对；裁判也可能出错。对 Android 动作，以系统实际状态或工具返回验证结果。

参考入口：[官方评测课件链接，待补核正文](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/reason_eval.pdf)。

## 11. P11：Model Editing

**课件要点**：针对目标知识或行为进行编辑；评价包括目标修改可靠性、泛化，以及对无关内容的局部性。课程区分不改参数与改参数的路线。

**理解补充**：改写一个问题后答对，不代表反向问法和相关推论都会更新。应同时测试目标问题、同义改写、关联问题和无关问题，检查修改是否一致及是否误伤。

**工程建议**：若只是业务资料变化，先评估能否用可追踪的检索资料更新；这便于记录来源与撤回。模型编辑是另一类工具，不能承诺无副作用，也不等于删除所有相关知识。

来源：[第10讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/edit.pdf)。

## 12. P12：Model Merging 与 Task Vector

**课件要点**：对于共同基础模型的微调结果，可用参数差值表示任务向量，并尝试组合这些变化。

$$\tau_A=\theta_A-\theta_0,\qquad
\theta_{merge}=\theta_0+\alpha\tau_A+\beta\tau_B$$

**理解补充**：向量相加是参数空间操作，不是把两个模型的答案拼起来，也不保证能力线性叠加。结构、参数对应关系与共同基座等条件很关键；不同任务的变化可能冲突。

**工程建议**：融合后同时评估两个目标任务和通用能力，保留各模型基线。当前入门项目无需先做融合；它也不等于运行时把请求路由给不同模型。

来源：[第11讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/merging.pdf)。

## 13. P13：语音语言模型

**课件要点**：本讲聚焦语音生成，介绍语音 Token、编码与还原，以及把语言模型训练思想用于语音的路线；也对比文本中转的语音处理方式。

**理解补充**：ASR 将声音转成文本，TTS 将文本转成声音。`语音 → ASR → 文本 LLM → TTS` 便于分模块排错，但文字中转可能丢失语调和说话风格信息。语音 Token 不等于识别后的文字 Token。

**工程建议**：手机助手先验证串联系统，再按需求探索更紧密的语音模型。除了答案正确，还要检查首音延迟、打断、回声、取消，以及重试时是否重复执行动作。

来源：[第12讲官方课件](https://speech.ee.ntu.edu.tw/~hylee/ml/ml2025-course-data/speech.pdf)。

## 14. 把概念落成一个最小项目（原创工程建议，待执行）

### 项目：只读 Obsidian 学习助手

输入一个学习问题，允许搜索 `agent开发/` 内的笔记，输出有依据的回答；资料不足时说明缺口。此项目是建议，本次没有实施或运行。

建议先只开放两个接口：

```text
search_notes(query) → [{path, heading, snippet}]
read_note(path)     → {path, content}
```

实现步骤：

1. 先完成固定检索问答：输入问题、关键词搜索、读取命中文件、生成带引用回答。
2. 再让模型决定是否检索、检索什么，以及是否需要第二次读取，观察自主选择是否带来收益。
3. 执行器校验工具名、参数和解析后的实际路径，限制在授权目录内；笔记内容按资料处理，不当作新系统指令。
4. 记录任务目标、工具调用、返回结果、结束原因和耗时；把模型生成的“已找到”与实际搜索结果分开。
5. 设最大工具轮数，例如先用 3 轮作为实验初值；到限额时返回已取得的证据和未解决问题，而不是无限重试。
6. 加入记忆实验：仅保存明确的学习偏好或已验证经验，并记录来源与更新时间；比较有无记忆时的表现。

### 最小测试集

| 输入情形 | 预期行为 |
| --- | --- |
| 库中明确写过的概念 | 找到笔记，回答与原文一致 |
| 库中不存在的资料 | 明确缺资料，不编造来源 |
| 同一事实有新旧版本 | 根据更新时间和明确撤回信息处理冲突 |
| 搜索为空、读取失败 | 返回可诊断原因，按预算停止 |
| 笔记里夹有“忽略规则”文字 | 作为检索内容，不改变执行权限 |
| 用户要求写入或访问目录外文件 | 当前只读原型不执行，说明能力边界 |

建议先准备约 20 个任务，比较“直接回答 / 固定 RAG / Agent 循环”三条路径；记录成功数、无依据断言、调用数和延迟。20 是练习规模建议，不是统计可靠性的保证。

### 迁移 Android 的建议

文本链路成熟后，增加 Kotlin 调用端、可取消的异步任务与持久化任务状态；工具用明确接口暴露。重试前核对动作是否已经完成，避免重复创建记录或重复提交。模型可提议动作，权限和执行结果仍由系统侧控制。

## 15. 自测问题与复习抓手

- **Token 为什么不等于字？** 它取决于模型的表示与分词方式。
- **检索到新资料是否等于训练？** 不是；可仅改变推理时输入。
- **Agent 如何不训练也“从经验调整”？** 存储经验并在后续上下文检索使用。
- **工具调用为什么不等于动作完成？** 还要经过程序校验、执行和结果确认。
- **微调后目标分数提高为什么仍需回归？** 旧任务和对齐行为可能退化。
- **长推理为什么不必然更好？** 额外步骤既消耗资源，也可能增加错误。
- **模型解释自己能否代替机制分析？** 不能；自述是输出，不是内部计算测量。
- **模型融合后为什么仍需测试？** 参数变化可能相互干扰。
