# 端侧 Agent 入门实战计划

## 起点与原则

> 背景更新：用户已确认有一定 Python 基础，跳过基础语法课，按项目需要同步学习。第一周直接做模型 API 与工具调用，不要求先完成 Python 入门课程。

面向 Android 系统框架工程师转型手机厂智能体岗位。建议先在普通 Android App 内完成执行闭环，再引入 IPC 与端侧模型。每周 10—15 小时为参考假设；用户实际 Kotlin、Python 基础、可用设备和时间尚未确认。以下均为建议，未表示项目已经创建或学习已经开始。

首个项目：Kotlin 编写的本地笔记/待办助手。先用文本交互和云模型，工具仅作用于 App 自己的数据。暂不引入跨应用操作、语音、多 Agent 或模型训练。

## 第一周：从接口到工具调用

1. 建立学习笔记和独立实验工程，整理一个可用模型接口的官方文档，确认流式、结构化输出和工具调用能力及费用。
2. 在开发机写一个最小调用脚本，观察完整请求、响应、错误与工具调用结构。开发机密钥使用环境变量，不提交仓库；Android 客户端不内置长期云密钥。
3. 用假模型和假工具完成 Kotlin 执行循环，定义模型接口、工具接口及任务状态，先验证逻辑再接真实接口。
4. 接入具备校验能力的开发代理服务，代理保管云密钥；或使用供应商明确支持的客户端认证方案。避免公开无鉴权代理。普通笔记本/开发机可承担实验代理，不需要先购买 GPU。
5. 先实现只读工具 `search_notes(query)`，让模型读取结果后回答。检索初期用数据库关键词查询即可，无需先建向量库。
6. 加入 `create_todo(title)`：界面确认后执行，使用持久化操作 ID 防止同一次操作被重复写入。
7. 复盘一周：画执行链路，记录模型选错工具、参数错误、工具失败等案例。

## 首月交付

| 周次 | 重点 | 验收标准 |
| --- | --- | --- |
| 第 1 周 | 模型 API、工具结构、最小循环 | 模型选择搜索工具，拿到真实工具结果后回答；创建操作有确认 |
| 第 2 周 | Kotlin 协程/Flow、聊天 UI、Room、流式输出 | 用户可查看执行状态、取消请求；数据持久化；不把单纯聊天当成 Agent 完成标准 |
| 第 3 周 | 状态机、超时、停止条件、重试与恢复 | 工具失败可解释；执行有步数/时间上限；不盲目重放结果未知的写操作 |
| 第 4 周 | 执行追踪、固定任务集、回归与演示 | 建议准备 20—30 个正常/异常案例，形成成功率、错误操作与耗时报告；该数量仅作学习起步样本 |

## 参考执行链路

用户请求 → 加载允许使用的上下文/工具 → 模型回复或提出工具调用 → 校验工具、参数和权限 → 必要时请求确认 → 执行并持久化结果 → 将结果返回模型 → 继续或结束。

宿主程序管理授权、状态、预算和停止条件，模型只提出调用。状态建议包括待处理、模型生成、待确认、工具执行、成功、失败、取消；按项目需要扩展。

## 第二阶段

- 第 5—6 周：将受控工具能力拆成独立服务，使用 Binder/AIDL，验证进程死亡、断连、重连和资源释放。
- 第 7—8 周：选择一种适合现有设备的本地推理运行时，接入统一模型接口，测试端云路由。模型是否支持工具调用需单独验证，可先限定本地摘要/分类而保留云端复杂规划。
- 后续按岗位与项目需要增加语音、个人知识 RAG、屏幕理解和系统级能力。

## 学习方式与资料

每次只解决当前项目需要的问题：模型接口官方文档 → Android 官方协程/架构文档 → 工具调用与执行机制 → 本地运行时官方示例。先读请求响应与可运行示例，再按失败案例补理论。

每周留下代码、设计取舍、失败案例、指标四类记录。模型基础先覆盖 Token、上下文、采样、Embedding、结构化输出及幻觉；训练和推理内核不作为首月前置条件。
