# 端侧智能体岗位匹配与路线调整

## 依据与边界

依据用户提供的两张岗位截图。个人已知背景仅为 Android 系统框架开发工程师，未确认年限、项目职责、Kotlin 与应用架构经验、AI 项目经验及学历；不据此给出个人匹配百分比。以下是岗位解读与调整建议，尚未视为用户已确认的新计划。

## 岗位要求摘要

- 设计端侧智能体应用架构，覆盖推理调度、会话、Function Calling、多模态和端云协同。
- 与产品和系统平台团队协作，完成 Android 落地与性能优化。
- 跟踪轻量化模型、Agent、多模态进展，推进创新与专利。
- 要求 Kotlin/Java、Android 框架（Binder、进程通信、生命周期、SystemUI、无障碍服务）、大型 App 架构及重构。
- 要求移动端架构模式、性能与质量意识，以及 Prompt、Function Calling、RAG、工具编排。
- 要求方案设计、攻坚、落地和沟通协作；AI 工作经验要求注明优秀者可放宽。
- 终端 AI 产品核心模块落地为加分项。

## 判断

与 AI 智能体与应用开发高度相关，细分方向为 Android 端侧/系统级智能体架构与应用落地。与个人已有系统背景存在直接交集；个人整体匹配程度需要项目证据核实。

职位名称是否达到专家级不能单凭截图确定。职责包含架构、跨团队落地、性能与技术创新，准备时应展示模块或系统的负责经历和量化结果。

## 能力差距与准备重点

| 领域 | 当前判断 | 准备重点 |
| --- | --- | --- |
| Android 框架与 IPC | 与已有背景方向一致，深度待核实 | 服务设计、生命周期、权限、故障恢复与实际成果 |
| Kotlin 与大型 App 架构 | 待确认，系统开发不自动等同于 App 架构经验 | 协程、Flow、MVVM/MVI、模块化、流式 UI |
| Agent 核心 | 尚无已确认的落地证据 | 工具循环、参数校验、取消、幂等、执行预算、会话恢复 |
| 端侧推理与端云协同 | 待补证据 | 模型加载与释放、并发调度、设备能力检测、路由与回退 |
| 多模态 | 待补证据 | 先文本，再语音输入与流式输出，最后图片理解 |
| 性能与质量 | 可迁移系统方法，但 AI 指标需要新增 | 首 Token 延迟、生成吞吐、P95 耗时、内存、功耗、温升、任务成功率 |
| 专家级交付 | 待项目证明 | 架构取舍、跨团队接口、评测报告、失败复盘、业务价值 |

## 相对原路线的调整建议

- 将“Android + Agent + 端云协同”升级为主线；Python 保留为服务、评测和实验工具。
- 保留工具调用、上下文工程、评测与安全；RAG 先达到支持场景的水平，再按需要深入。
- 主作品由系统日志诊断 Agent 调整为 Android 端侧智能助手；日志诊断保留为工具模块或副项目。
- 不把训练、微调、多 Agent 和底层推理内核作为初期必需项；确认岗位边界后再决定深度。
- 推理调度需先确认是应用层运行时集成与资源调度，还是 C++、算子和硬件后端优化。

## 推荐主项目

Android 端侧智能助手：自然语言输入 → 会话/任务管理 → 模型路由 → 工具调用 → Android 能力执行 → 执行结果反馈。

模块建议：Kotlin 客户端、Agent 执行状态机、统一模型接口、云端模型接入、本地模型接入、工具注册与权限、持久化与恢复、评测与监控。

首批工具建议使用可控范围：应用内笔记检索、创建待办、获取应用自身诊断信息、通过公开 Intent 打开系统页面。需要系统权限的操作在可控 AOSP/系统签名环境另行验证，不能假设普通 App 拥有系统权限，也不能把无障碍视作无限制跨应用控制接口。

项目验收：至少覆盖正常完成、无网络、无权限、工具失败、用户取消、进程重建、模型输出非法参数、重复执行等场景，形成指标和取舍报告。具体设备与性能目标通过实测确定。

## 调整后的 16 周建议

| 时间 | 重点 | 交付 |
| --- | --- | --- |
| 第 1—4 周 | Kotlin/协程与模型 API、文本工具调用 | 云端模型驱动的 Android 助手 |
| 第 5—8 周 | 状态机、工具权限、会话持久化、取消恢复 | 可恢复、可追踪的多步任务 |
| 第 9—12 周 | 一种本地运行时、设备适配、端云路由 | 本地与云端可切换及受控回退 |
| 第 13—16 周 | 语音链路、性能评测、失败集、架构文档 | 可演示作品与量化报告 |

## 待向招聘方确认

- [ ] 是应用层、系统应用还是 Framework 服务岗位？可用权限和设备环境是什么？
- [ ] 推理调度侧重运行时集成还是内核、算子与硬件优化？
- [ ] 当前模型和运行时栈是什么，端侧与云端分别承担什么？
- [ ] 核心目标是对话、多步任务、跨应用操作还是主动服务？
- [ ] 专家级验收更侧重架构、业务效果、性能还是专利创新？

## 招聘机会观察（2026-10-24）

本次公开招聘抽样能确认此类机会存在，但未取得跨平台去重的在招总数，不能据搜索命中量推导岗位规模或增长率。页面可访问也不保证职位仍有有效 HC。
