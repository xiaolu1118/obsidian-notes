# Agent 学习执行总表与视频导航

## 使用说明

这是当前唯一执行顺序。早期 8/10/12/16 周路线作为历史参考，后续跟学以本文为准。背景已确认：Android Framework 有基础、Python 有一定基础、AI/Agent 从零开始。跳过 Python 语法，保留 AI 基础学习；异步、Web 服务、部署在实践中按需补齐。

按每周 10—12 小时、16 周估算，实际以验收为准；未开始的任务不标为完成，不承诺完成即可达到专家岗。贯穿项目为“学习笔记与待办助手”，先 Python 命令行，再服务化，最后 Android。

视频链接来自本次对话已整理资料。李宏毅合集分 P 依据已归档的元数据核验结果；黑马等课程没有完整分 P 核验，不编造课号或分钟时间戳，按主题定位。B站转载、页面限制、依赖变更与评价边界见 [[B站Agent课程精选与观看顺序]]。未核验评论区口碑，不视为评分榜。课程公开不代表模型/API实验免费。

## 三、阶段 1：基础认知（第 1—2 周）

### 观看

1. [V1：生成式 AI](https://www.bilibili.com/video/BV1YeT7zBEPi/?p=1)。关注 Token、生成、上下文、训练与推理、幻觉。
2. [V2：Agent 原理](https://www.bilibili.com/video/BV1YeT7zBEPi/?p=2)。关注目标、观察、动作、工具、规划和反馈。
3. 配套 [[李宏毅2025机器学习课程视频导读]]、[[李宏毅2025机器学习核心知识详解]]。

### 每周动作

- 第 1 周：两次各看约 30—45 分钟 V1，其余时间复盘/实验；对同一个问题添加不同上下文，记录变化；整理 10 个术语。
- 第 2 周：分两次看 V2；画聊天、固定工作流、工具循环三种图；准备 5 条虚构笔记、10 个助手任务和禁止动作。

### 验收

- [ ] 解释训练与推理、Token与字符的区别。
- [ ] 说明模型不知道私人笔记时为什么需要提供上下文或检索。
- [ ] 能画出模型提出调用、程序执行、结果回传的循环。
- [ ] 分清聊天、RAG、工作流、Agent，不把工具调用等同于执行权限。

本阶段不要求训练模型、学习 Transformer 数学或搭建 Android 工程。

## 四、阶段 2：模型应用（第 3—4 周）

### 视频定位

[V3 黑马主课](https://www.bilibili.com/video/BV1yjz5BLEoY/)，在选集中找模型接入/API、环境变量、提示词、LangChain 模型调用、输出解析与流式等主题；标题可能变化，以实际目录为准。目录没有覆盖的练习用供应商官方文档补，不将自编练习冒充视频章节。

### 动手

- 第 3 周：建立独立虚拟环境，按课程版本安装；使用环境变量读取密钥，完成普通回答与结构化输出，记录脱敏请求/响应。
- 第 4 周：增加多轮历史、流式显示、上下文裁剪；模拟鉴权失败、网络错误、超时和非法 JSON。按需补异常/异步，不重学语法。

### 验收

- [ ] 不依赖未知辅助函数也能解释请求与响应。
- [ ] 分清 SDK 包装与实际模型 API。
- [ ] 对错误有明确反馈，重试有限制，密钥不写入仓库。
- [ ] 能解释提示能影响输出但不能保证事实或格式永远正确。

产物：命令行多轮助手、环境配置说明与失败笔记。

## 五、阶段 3：RAG 和上下文（第 5—6 周）

### 观看

1. [V3 的 RAG 部分](https://www.bilibili.com/video/BV1yjz5BLEoY/)：切块、Embedding、向量检索、文档加载、RAG流程和项目。
2. [V6 上下文工程](https://www.bilibili.com/video/BV1Esx5zXExD/)：建议在基础检索跑通后观看。

### 动手

- 第 5 周：用 5—20 篇虚构/脱敏学习资料，先做关键词搜索基线，再用一种向量检索方案；打印模型最终收到的资料片段。
- 第 6 周：增加文件名或片段来源；测试无答案、相似术语、冲突材料。分开管理系统规则、用户请求、历史与外部资料；比较至少两种切块/检索设置。

### 验收

- [ ] 解释 Embedding 与生成模型的不同职责。
- [ ] 能定位“没检索到”和“检索到但回答错”。
- [ ] 有来源再引用，无依据不伪造引用。
- [ ] 不将外部资料当作高优先级执行指令。

产物：学习资料问答助手、10 个检索案例及对照记录。先不研究复杂图 RAG 或重型向量集群。

## 六、阶段 4：单 Agent 和工具执行（第 7—8 周）

### 观看

1. [V3 的 Agent 部分](https://www.bilibili.com/video/BV1yjz5BLEoY/)：工具、Agent 创建、循环、流式事件与项目。
2. [V4 Hello-Agents 范式](https://www.bilibili.com/video/BV12Z63BCEn6/)，配合 [官方图文](https://hello-agents.datawhale.cc/)或[源码](https://github.com/datawhalechina/hello-agents)。先学 ReAct，规划和反思为选修。

### 动手

- 第 7 周：做 `search_notes`、`list_todos` 两个只读工具，定义参数结构、校验和结果；先用普通代码实现循环，记录工具事件，不要求输出模型隐藏推理。
- 第 8 周：加 `create_todo`，用户确认后写入；保存操作 ID 防重复，设置时间/步数上限；模拟不存在工具、参数错误、失败、拒绝与取消。

### 验收

- [ ] 能完成搜索后创建待办的多步任务。
- [ ] 模型不能绕过程序授权与参数检查。
- [ ] 拒绝不写入，同一操作不重复创建。
- [ ] 达到预算会停止，结果未知时先查询实际状态。

产物：首个完整单 Agent，而非单纯聊天或检索问答。

## 七、阶段 5：状态和编排（第 9—10 周）

### 视频定位

[V5 LangChain/LangGraph/LangSmith](https://www.bilibili.com/video/BV178w1z7EHQ/)，定位状态、图、条件分支、持久化、监控和调试。是否含每一项以当前目录为准；持久化/确认不足时用[官方 LangGraph 文档](https://docs.langchain.com/oss/python/langgraph/overview)补齐。

### 动手

- 第 9 周：把原助手映射到状态、节点和边；SQLite 保存会话、任务与工具结果；分离对话历史、任务检查点和长期偏好。
- 第 10 周：实现等待确认、重启恢复、失败出口和取消传播；查看每步 Trace，对比手写版本与框架版本。

### 验收

- [ ] 两个会话不串数据，重启后有正确状态。
- [ ] 恢复不盲目重放有副作用的工具。
- [ ] 能解释框架带来的收益和额外复杂度。
- [ ] 根据轨迹定位模型/工具/状态问题。

产物：可恢复执行器、状态图、失败恢复说明。此时不要求 Mem0、MemoryOS 或多 Agent。

## 八、阶段 6：工程化、评测和部署（第 11—12 周）

### 观看与补充

- [V5 监控/调试/评估相关内容](https://www.bilibili.com/video/BV178w1z7EHQ/)。
- [V7 李宏毅评估课](https://www.bilibili.com/video/BV1YeT7zBEPi/?p=10)，24:03，建立评价观念。
- 需要更完整实验时选 [V8 Evaluating AI Agents](https://www.deeplearning.ai/courses/evaluating-ai-agents)：Trace、组件、轨迹与实验相关主题。
- 服务端按需查 [FastAPI 官方教程](https://fastapi.tiangolo.com/tutorial/)；它是文档，非已核验的B站视频课。

### 动手

- 第 11 周：封装最小服务和流式接口；配置凭据、客户端鉴权、会话隔离与日志脱敏。先本地运行，再按项目需要容器化。
- 第 12 周：准备 30 个起步任务（10 搜索、10 待办、10 异常），记录成功率、错误操作、调用次数与耗时；只改一个变量做对照。样本数量不是生产充分性标准。

### 验收

- [ ] 非 Notebook 环境也能运行，有依赖版本与配置说明。
- [ ] 回归可重复执行，失败可以分类。
- [ ] 写操作成功由实际数据判断，不只看模型自评。
- [ ] 有一页改进前后报告与至少三个失败案例。

若仍需老师督学/代码批改，此阶段再评估[极客时间工程化实战营](https://u.geekbang.org/subject/10/1010551)；完整训练营需要另排时间，不要求塞进两周。

## 九、阶段 7：Android 迁移（第 13—14 周）

这是自编实验阶段，目前没有已充分核验、完整匹配的B站专项主课，不用通用 Agent 视频冒充 Android 教程。

### 配套官方资料

- [Android 协程](https://developer.android.google.cn/kotlin/coroutines?hl=zh-cn)
- [Flow](https://developer.android.google.cn/kotlin/flow?hl=zh-cn)
- [Room](https://developer.android.com/training/data-storage/room?hl=zh-cn)
- [AIDL](https://developer.android.com/develop/background-work/services/aidl?hl=zh-cn)

### 动手

- 第 13 周：实现 Kotlin `ModelClient`、`AgentRunner`、`ToolExecutor`、`SessionStore` 与 ViewModel。先假模型测试，再通过受保护服务或供应商支持的认证接云模型。无需把 Python 框架搬入 APK。
- 第 14 周：Room 保存任务；一个受控工具通过 Binder/AIDL 服务暴露，测试断连、死亡和重连、旋转与进程重建。

### 验收

- [ ] 与 Python 基线完成相同任务，UI 与任务状态一致。
- [ ] APK 不含长期云密钥，取消后不继续执行下一步。
- [ ] 页面变化、进程恢复不造成重复创建。
- [ ] 区分普通App、系统App与Framework权限，不假设可以无限控制其他应用。

产物：Android 助手与系统集成设计文档。

## 十、阶段 8：端侧推理与作品交付（第 15—16 周）

### 资料入口

- [LiteRT-LM Android 入门](https://developers.google.cn/edge/litert-lm/android)
- [Google AI Edge Gallery](https://github.com/google-ai-edge/gallery)
- [Perfetto 文档](https://perfetto.dev/docs/)
- 语音理论选看：[李宏毅语音语言模型 P13](https://www.bilibili.com/video/BV1YeT7zBEPi/?p=13)，1:31:19；它是理论课，不是 ASR/TTS Android 接入教程。

### 动手

- 第 15 周：按运行时支持选择设备/模型；先实现本地摘要或分类，再接统一模型接口。离线、模型未就绪、云超时分别处理；数据能否上云由策略决定。
- 第 16 周：测量加载、首 Token/任务耗时、内存与持续负载，记录设备、版本和输入；整理演示、架构图、回归、性能与取舍。有余力再加入语音，不为增加功能牺牲可靠性。

### 验收

- [ ] 真机离线完成至少一项明确能力。
- [ ] 模型不可用有合理反馈，回退符合数据授权。
- [ ] 有可复现设备测试记录，而不是只说“速度快”。
- [ ] 能讲清三项设计取舍、三类失败与对应修复。

本地运行时是学习选型之一，不假设所有手机厂使用相同栈或具备 Google 服务。
