# 主流手机厂商的大模型部署方式

## 问题与结论

用户关心主流厂商如何在手机本地部署大模型，以理解端侧 Agent 的工程方向。资料于 2026-11-14 再核验，依据公开官方资料，不代表获得厂商内部实现。用户已明确希望入门此赛道，尚未选定品牌、设备与具体岗位分支。

从已公开产品架构归纳，常见路线为：经过端侧适配的模型 + 操作系统级 AI 能力管理 + 本地/云端按任务协作。不能将所有厂商、型号、地区和功能视为同一实现，也没有依据认定所有厂商采用同一个运行时。

需要区分三个维度：

1. 计算位置：纯端侧、纯云端或端云协同。
2. 能力承载：系统共享模型服务，或 App 自带模型与运行时。
3. 底层执行：推理引擎通过硬件后端调用 CPU/GPU/NPU；这与模型是否上云是不同问题。

## 本地部署在工程上通常包含什么

以下是工程归纳，不是每个品牌内部实现的已确认清单：

1. 在离线训练环境中完成模型训练和端侧适配，按需要采用蒸馏、量化、稀疏化等方法；手机主要承担推理，个性化记忆不必通过更新权重实现。
2. 将适配模型、Tokenizer、配置等作为受管理资产预置或下载，建立版本校验、设备兼容与更新机制。具体分发方式按平台确认。
3. 由系统 AI 服务或应用运行时加载模型，管理会话、KV Cache、内存、并发、取消、资源释放及温控策略。
4. 推理引擎将支持的算子交给 CPU/GPU/NPU 后端；算子覆盖、量化格式与内存传输决定收益，不能假定全模型或所有环节都由 NPU 执行。
5. 根据模型能力、网络、数据策略、延迟与资源预算选择本地执行、云端执行或拒绝/降级；上云是执行位置改变，不一定是将同一个模型逐层拆到端云运行。

例如 3B 参数全部按 4 bit 存储，纯权重理论约为 1.5 GB（十进制）。实际还需量化元数据、KV Cache、激活、工作区和运行时，因此不能把模型文件大小直接当成总内存需求。此处仅为计算示例，不代表当前手机统一采用 3B/4 bit。

## 与 App 自带模型的区别

- 系统共享服务：App 调 SDK/IPC，由平台统一提供模型能力。Google AICore 是有明确官方文档的实例，可避免多个应用分别下载同一个基础模型；调用受设备、版本和 API 规则约束。
- App 自带运行时：开发者选择模型，使用 LiteRT-LM、llama.cpp、MNN 等适合目标设备的方案，自行承担资产下载、兼容、加载、内存与生命周期管理。这是独立应用和学习验证的可选路线，不能直接当作手机厂商量产实现。
- 工程上不宜假定手机厂商将桌面 Ollama 环境原样搬入 ROM，也不能仅凭用了某品牌芯片就确定推理引擎。

## 对职业转型的意义（建议）

### 面向 Agent 认知较少者的入门顺序（2026-11-14）

将端侧赛道拆为三条：应用/Agent 执行、模型服务与系统集成、推理引擎/硬件优化。针对用户 Android Framework 背景，建议以模型服务与系统集成为职业主线，用应用实验理解全链路；不把训练、量化算法研究、NPU 算子开发作为入门前提。

先区分“手机执行任务”和“模型在手机本地推理”：云端模型也可驱动本地工具；本地模型只做摘要则未必构成 Agent。普通 App 调系统公开能力、应用内自带运行时、厂商特权系统服务是不同接入边界。

建议四阶段，每阶段约一周只是实验预算，按基础调整：

1. 在开发机完成 [[agent开发/端侧Agent入门实战计划|最小只读日志工具循环]]，理解模型提议、宿主执行、结果回传和停止。
2. 选一种本地路线真机运行：设备符合条件则用 ML Kit/AICore；否则参考 LiteRT-LM 官方示例或 Google AI Edge Gallery，核对其设备、模型和后端支持。二者是替代选项，不同时铺开。先完成离线文本生成与性能记录。
3. 在普通 App 中将推理放入独立进程 Service，通过 AIDL 调用，处理加载、排队、流式返回、取消、Binder 死亡与资源释放。独立进程服务用于模拟系统工程问题，并不等于新增 system_server 服务。
4. 给服务接两个应用内工具，例如 search_notes 与 create_todo，增加参数校验、写操作确认、幂等及失败记录；本地模型若不擅长工具调用，可暂承担摘要/分类，工具规划由已验证的模型承担。数据不允许上云时应拒绝或降级，不能强制回退云端。

建议作品名：Android Agent Runtime Demo。验收包括断网、拒绝权限、进程重建、取消、重复请求、内存压力，以及加载耗时、首 Token 延迟、生成速度、PSS、任务成功率。功耗与温升需固定设备和测试条件，不能仅凭一次运行推断。

本轮核验的 [ML Kit GenAI](https://developers.google.com/ml-kit/genai) 明确建立在 AICore 上；[LiteRT-LM](https://developers.google.com/edge/litert-lm/overview) 提供本地运行与工具使用支持，并链接 AI Edge Gallery 示例。这些是学习入口，不代表国内厂商采用相同内部实现。

已完成：公开资料复核、路线细化和归档。待确认：现有手机型号/SoC/内存/系统、每周投入时间、偏系统集成还是推理优化。未安装运行时、未完成真机性能测试。

对 Android Framework 背景，优先学习“模型服务的客户端和系统集成”：Binder/AIDL、模型会话与资源调度、端云路由、权限、取消恢复、工具执行与评测。再根据 JD 决定是否深入推理运行时和 NPU 优化。

建议实践：先在 App 内真机跑通一种运行时，再把推理封装为独立服务，通过 AIDL 调用，加入请求队列、取消、服务死亡处理、模型版本与性能观测。这个项目模拟系统集成问题，不意味着已经复刻厂商架构。用户尚未确认执行。
