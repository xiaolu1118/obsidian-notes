# 机器人开发技术栈与入门路线

## 背景与状态

- 用户本轮希望了解机器人开发技术栈。
- 既有聊天笔记记录用户为 Android 系统框架开发工程师；可迁移经验仍需结合实际工作确认。
- 尚未确认机器人类型、目标岗位、硬件预算或学习投入。以下为全景梳理与建议，不代表已确定转型或改变 Agent 学习优先级。

## 核心认识

机器人软件围绕“传感器采集 → 感知与状态估计 → 规划决策 → 控制执行 → 反馈”构成闭环。不同岗位深入其中一部分，入门无需掌握全部领域。

| 层次 | 重点知识与工具 | 解决的问题 |
| --- | --- | --- |
| 编程与系统 | C++、Python、Linux、Git、CMake、并发、网络、调试 | 编写和部署稳定运行的机器人软件 |
| 数学基础 | 线性代数、微积分、概率、优化、坐标变换、旋转与四元数 | 表达位置姿态、噪声和运动关系 |
| 硬件与嵌入式 | 电机、编码器、IMU、相机、激光雷达；MCU、RTOS、UART、CAN、EtherCAT | 传感器与执行器接入、底层实时控制 |
| 机器人中间件 | ROS 2、节点、Topic、Service、Action、QoS、tf2、URDF、Launch | 模块通信、坐标树、模型和启动配置 |
| 感知与定位 | OpenCV、PCL、标定、时间同步、里程计、EKF、SLAM | 理解环境并估计机器人状态 |
| 规划与控制 | 搜索、轨迹规划、运动学、动力学、PID、MPC | 计算可行运动并稳定执行 |
| 任务与交互 | 状态机、行为树、任务调度、人机交互 | 编排任务、恢复失败和管理状态 |
| 仿真与工程 | RViz、Gazebo；按项目选择 MuJoCo/Isaac Sim；rosbag2、日志、测试、部署 | 验证算法、回放问题和交付系统 |

ROS 2 是机器人软件框架与通信生态，不代替 Linux，也不自动保证硬实时。RViz 用于可视化，Gazebo 用于物理仿真。

## 方向分支

- 移动机器人：轮式运动学、里程计、SLAM、定位、代价地图、Nav2、避障与导航。
- 机械臂：正逆运动学、坐标变换、碰撞检测、轨迹规划、MoveIt 2、ros2_control、抓取与标定。
- 人形/四足：刚体动力学、接触与平衡、状态估计、全身控制；按需求学习强化学习和模仿学习。
- 机器人平台软件：Linux、驱动接入、ROS 2 通信、生命周期、并发、性能、部署与故障诊断。
- 具身智能：在机器人基础上补充 PyTorch、视觉语言模型、VLA、示教数据、模仿学习、评测与部署。高层模型任务需通过受约束的执行接口接入控制系统。

## 结合 Android 背景的建议

优先评估机器人平台软件/系统集成方向：系统服务、IPC、并发、设备管理、性能分析和故障定位经验有迁移价值。需要补齐 Linux/C++ 工具链、ROS 2、坐标变换、传感器时间同步与基础控制。熟悉 Android Framework 不等于已经具备 MCU、驱动或控制算法经验。

## 建议实施步骤

1. 复习 Linux、C++、Python 和构建调试工具，能独立构建并定位一个程序的问题。
2. 学 ROS 2 通信、参数、Launch、tf2、URDF、rosbag2；实现传感器发布、数据处理、动作反馈及取消。
3. 先用仿真完成一条闭环，再接入硬件。移动机器人可从小车建图、定位、导航开始；机械臂可从仿真机械臂运动规划开始。
4. 加入日志、数据回放、超时、取消、故障恢复与量化指标，形成可复现项目。
5. 基础闭环完成后，再按目标岗位加入视觉、抓取或自然语言任务编排。

项目验收可包含任务成功率、定位误差、到达误差、耗时和故障恢复表现；指标阈值由具体任务确定。

## 待确认

- [ ] 主要目标：技术了解、业余项目，还是职业转型。
- [ ] 目标方向：移动机器人、机械臂、人形/四足、平台软件或具身智能。
- [ ] C++、Linux、数学与硬件基础，以及可投入时间。
- [ ] 确认设备及驱动支持后再选择匹配的 ROS 2、操作系统、仿真器版本。
